Contract for THIS export (different from the earlier expert-only export)
- Use trex/train.json, 31 action dimensions, 16-step chunks at 30 Hz.
- action_supervision_mask is all true: train all 31 valid executed-action axes, including policy actions after interventions and policy hand commands during G.
- human_supervision_mask [16,31] records ownership: F = arm+hand, G = arm only. It is provenance, NOT the loss mask in this baseline. Do not substitute it for action_supervision_mask or filter to human-only rows.
- action_is_pad=True means temporal padding OR an invalid handoff action target. It can contain internal holes. Preserve later valid steps; never truncate the chunk at its first true value. Placeholders are not expert action labels.
- For both losses, valid = (~action_is_pad)[...,None] & action_supervision_mask. Compute sum of squared velocity error only at valid entries, divided by max(number of valid scalar entries,1).
- Train/validation split must group by source_episode_id, not segment or row; use the same seed and ratio for statistics and training.
- Keep image_preprocessing.json beside train.json. Preserve dataset-native per-view dimensions and do not recrop exported images. Preserve the checkpoint's modality, state and action conventions.
- Earlier expert-only README text says G hand targets are excluded. That applies when the dataset's axis mask disables them; it does NOT describe this successful-continuous export, whose mask enables them.

Normalization and checkpoint initialization
For a warm-start comparison, keep the compatible deployed checkpoint's stats_data.json as the explicit --stats_path; changing normalization changes the numerical meaning of its learned action/state mappings. Preserve these same statistics at deployment via the saved checkpoint. This is a choice for the experiment, not an exporter requirement.
If intentionally refitting normalization, fit only training sources with the masked prepare_stats.py; never use all-source train_statistics.json by accident. For example, from the pipeline root in the configured training environment:
  python training/trex/prepare_stats.py --data "$DAGGER_DATA/trex/train.json" --output "$DAGGER_STATS" --seed 42 --val-ratio 0.1
Set DAGGER_STATS to a new experiment file for refitting, never to the original checkpoint statistics. Retain the generated split report. Applying new scaling to an existing checkpoint requires deliberate validation; it is not numerically equivalent to continuing its old training.

From the T-Rex repository root, activate the compatible training environment and set server-local absolute paths:
  export DAGGER_DATA=/path/to/oct14_15_success_continuous_v4
  export DAGGER_CHECKPOINT=/path/to/compatible_31d_checkpoint
  export DAGGER_STATS="$DAGGER_CHECKPOINT/stats_data.json"
  export DAGGER_QWEN=/path/to/Qwen3-VL-2B-Instruct
  export DAGGER_DEFORM=/path/to/standard_deform.pth
  export DAGGER_OUTPUT=/path/to/new/dagger_training_runs
  export PYTHONPATH="$PWD"
  export WANDB_MODE=offline

For the matching F6+deformation, state-enabled checkpoint, run:
  python scripts/train.py \
    --model_path "$DAGGER_QWEN" --data_format json \
    --data_path "$DAGGER_DATA/trex/train.json" --stats_path "$DAGGER_STATS" \
    --resume_checkpoint "$DAGGER_CHECKPOINT" --resume_source midtrain \
    --output_dir "$DAGGER_OUTPUT" --log_dir "$DAGGER_OUTPUT/logs" \
    --experiment_name dagger_success_v4 --run_name smoke \
    --action_dim 31 --action_chunk 16 --use_robot_state 1 \
    --use_tactile_vec 1 --use_tactile_deform 1 --deform_encoder_ckpt "$DAGGER_DEFORM" \
    --use_tactile_vqvae 0 --use_flare 0 --tactile_intermediate_size 1536 \
    --training_stage 2 --cascaded_total_steps 10 --cascaded_split_step 6 \
    --distributed_backend none --gradient_checkpointing 1 \
    --train_bsz_per_gpu 1 --gradient_accumulation_steps 4 \
    --n_epochs 20 --learning_rate 1e-5 --weight_decay 0.01 \
    --warmup_rates 0.03 --max_grad_norm 1 --save_freq 1 --max_ckpts 3 \
    --seed 42 --val_ratio 0.1 --max_steps 10 --val_freq 10 \
    --max_val_batches 2 --num_workers 0

Match modalities and model configuration to the checkpoint's training_args.json. Do not add --image_size: preserve the exported per-view crop dimensions. --resume_source midtrain preserves the trained tactile expert. This warm-starts weights; it does not resume optimizer/scheduler/RNG state.

After finite-loss/backward/checkpoint checks pass, use a new run name, remove --max_steps 10, choose a deliberate epoch/update budget, and set suitable validation frequency/workers. The shown LR and epoch defaults are starting settings, not a tuned DAgger recipe. Evaluate against the same baseline task protocol; a lower SFT loss is not evidence of improved robot success. This is successful-trajectory uniform SFT, with no human-ownership weighting, progress classifier or failure learning.

If adding original demonstrations later, build an explicit combined manifest with globally unique source IDs and valid media paths; keep each source in one split and choose sampling ratios deliberately. Simply concatenating JSON with conflicting relative paths or source IDs is unsafe. The supplied smoke command uses only the successful DAgger export.
